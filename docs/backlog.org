** DONE [#2] v0 整包上传在处理函数里构造阻塞式客户端导致工作线程崩溃 :ARCHIVE:
:PROPERTIES:
:CREATED: [2026-11-05 Thu]
:END:
接口：POST /api/v0/upload/{kind}。
现象：请求得不到响应，连接被直接切断，服务进程不退出但已无法正常服务。
根因：阻塞式 HTTP 客户端内部持有一个运行时，它的创建与销毁只能在普通线程上进行；
该客户端在异步处理函数里被同步构造，运行时的创建与析构因此落在异步上下文中并触发中止。
同一位置的另外两处缺陷：请求体上限与实现不一致，且整包读入内存，大文件会先被拒或被撑爆。
现状：v1 逐帧接口已完全替代该路径，前端只在浏览器无法解码时回退到它。
处理方向：删掉整条路径，回退场景改为让前端提示不支持，不再上传整个文件。

CLOSED: [2026-11-07 Sat]
:END:

** [#3] 剪辑定位不是帧精确
:PROPERTIES:
:CREATED: [2026-11-05 Thu]
:END:
把素材剪成片段时，定位和输出起点与请求的时间点存在偏差，与关键帧位置相关。
现象：同一素材上，请求点位在关键帧之后与之前，取到的画面分别出现在期望时间之后与之前，
偏差量级在一帧到数帧之间，方向不固定。
影响：剪辑生成的测试素材字幕起止时间无法复现，基于这些素材的端到端断言不可信。
处理方向：输出时改成帧精确的定位与重编码，并在脚本里用画面临界点反查实际时间轴。
