接口：POST /api/v0/upload/{kind}。
现象：请求得不到响应，连接被直接切断，服务进程不退出但已无法正常服务。
根因：阻塞式 HTTP 客户端内部持有一个运行时，它的创建与销毁只能在普通线程上进行；
该客户端在异步处理函数里被同步构造，运行时的创建与析构因此落在异步上下文中并触发中止。
同一位置的另外两处缺陷：请求体上限与实现不一致，且整包读入内存，大文件会先被拒或被撑爆。
现状：v1 逐帧接口已完全替代该路径，前端只在浏览器无法解码时回退到它。
处理方向：删掉整条路径，回退场景改为让前端提示不支持，不再上传整个文件。

实现：新增 `GET /api/v1/streams/{id}/events`（Server-Sent Events）。
`FrameStream` 持有一个广播通道，开流、每帧入库、完成时各发布一次快照；
订阅者先拿当前快照再挂通道，不会漏掉订阅瞬间的状态。不存在的 id 不报错，
只发 keep-alive 注释——浏览器在首帧上传前就已经订阅。静默流按固定间隔重发当前状态，
避免代理掐断空闲连接。
前端改为 `EventSource`，每帧上传后显示服务端已收帧数与有字帧数，完成后自动断开。
测试：连接即得快照、未见流时空转、后订阅者立即拿到快照；实测 open→done 两个事件按序到达。
